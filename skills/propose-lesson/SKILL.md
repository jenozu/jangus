# Prepare a lesson proposal for review

**Trigger:** A verified run reveals a repeated, generalizable failure or improvement.
**Inputs:** Redacted symptoms, verified evidence IDs and the bounded suggested change.
**Platforms:** Windows and Ubuntu.
**Required tools:** None.

## Procedure
1. Separate observed facts and evidence references from proposed interpretations.
2. Write a brief draft recommendation without secret values or private workspace content.
3. Include affected scope, prerequisites, safe verification and a stable reference.
4. Mark the draft as unapproved. Do not insert it into operational memory retrieval.
5. Hand it to a human review process once Phase 6 approval storage exists.

## Stop and escalation
This is drafting guidance only. Phase 5 must not create an approved Obsidian record, alter execution permissions or claim a memory service is active.
